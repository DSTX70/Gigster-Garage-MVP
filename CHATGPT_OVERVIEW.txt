GIGSTER GARAGE - PROPOSAL SAVE BUG OVERVIEW FOR CHATGPT

THE PROBLEM:
When user tries to save a proposal in the web app, they get error "Failed to save proposal" (red toast notification). This happens on the INITIAL save, before they even try to save to Filing Cabinet.

WHAT'S BEEN FIXED (Backend is working ✅):
1. Schema validation - Changed projectId from .optional() to .nullish() to accept null values
2. Filesystem paths - Fixed PRIVATE_OBJECT_DIR to use absolute paths
3. Database records - Implemented proper Filing Cabinet document creation
4. Backend tested with curl - ALL PASSING

THE MYSTERY:
- Backend API works perfectly when tested directly with curl
- User gets error in browser but NO error appears in server logs
- This means: The request NEVER reaches the server
- Problem is in the FRONTEND code somewhere

WHERE THE BUG IS:
Frontend file: client/src/pages/create-proposal.tsx
The save mutation calls apiRequest() but something fails before the HTTP request is sent.

WHAT CHATGPT NEEDS TO DEBUG:
1. Check apiRequest function in client/src/lib/queryClient.ts
   - Does it throw errors that get caught by onError?
   - Is there error handling that prevents the request?

2. Check the save handler in create-proposal.tsx
   - Is the proposalData object malformed?
   - Are there undefined values that break something?

3. Frontend validation
   - Is there client-side validation blocking the save?
   - Are required fields missing?

4. Browser issues
   - Check network tab - is request being sent?
   - Check console - any JavaScript errors?
   - Check cookies - is session valid?
